1 · LIGHTHOUSE

Notas do Lighthouse

O Lighthouse é a ferramenta do Google que dá nota de 0 a 100 a uma página em quatro áreas: desempenho, acessibilidade, boas práticas e SEO. Rodamos o Lighthouse 12.8.2 nas 7 páginas do site, primeiro no estado em que estavam e depois das correções descritas na seção 2. No modo celular, o Lighthouse simula um aparelho intermediário numa rede 4G lenta, que é o cenário mais exigente.

3 · ARQUITETURA

Como o sistema está organizado

O CineBook é um aplicativo web progressivo (PWA) feito com HTML, CSS e JavaScript puro, sem framework. Todo o código roda no navegador. O Netlify entrega os arquivos e repassa as chamadas às APIs pelo próprio domínio do site, o que evita bloqueios de rede e de CORS.

Decisões de projeto

Sem framework. O site carrega só o que usa e roda em qualquer hospedagem estática. O preço é mais código escrito à mão para montar a interface.

Dados reais, nada inventado. Nota, avaliações, "onde assistir" e trailer só aparecem quando a fonte oficial confirma. Filme que ainda não estreou mostra a data de estreia no Brasil em vez de nota.

Reserva para cada serviço. Se o Google Books recusar pedidos, a busca de livros passa para a Open Library. Se o proxy do TMDB falhar, o site tenta a API direto. Sem internet, o service worker entrega a última cópia.

Senhas nunca guardadas em texto. A senha vira um hash PBKDF2-SHA256 com 600 mil iterações e sal próprio, pela Web Crypto API do navegador. Depois de várias tentativas erradas, o login fica bloqueado por um minuto.

4 · TESTES

No GitHub

O arquivo .github/workflows/testes.yml faz o GitHub Actions rodar todos os testes a cada push e a cada pull request, numa máquina Ubuntu limpa com Node 20 e Chromium. Cada commit ganha um ✅ ou ❌ na aba Actions, e as capturas de tela dos testes ficam guardadas para consulta.

O README mostra o selo com o estado atual, que fica verde quando todos os testes passam: Testespassing

Para evitar falso positivo, os testes novos foram rodados também no código antigo: eles falham lá (por exemplo, CLS de 0,474 e quatro janelas focáveis) e passam no código corrigido.

6 · PRÓXIMOS PASSOS

O que ainda dá para melhorar

  • Minificar e juntar os arquivos. O Lighthouse estima 114 KB a menos de JavaScript e 27 KB a menos de CSS com minificação, e cerca de 70 KB de CSS que nenhuma página usa.
  • Carregar traduções sob demanda. O i18n.js traz os 11 idiomas de uma vez (164 KB). Carregar só o idioma escolhido reduz o primeiro acesso.
  • Imagens do tamanho certo. Pedir ao TMDB pôsteres menores no celular (w342 em vez de w500) acelera o maior elemento da página inicial.
  • Contas no servidor. No site publicado, as contas ficam no navegador de cada pessoa. O backend em Python já existe; falta hospedá-lo para a conta funcionar em qualquer aparelho.
